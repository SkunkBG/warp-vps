# Два профиля: весь трафик и только AI

Два готовых варианта. Отличаются они ровно одним правилом маршрутизации —
outbound в обоих одинаковый.

| Профиль | Правило | Что уходит в WARP |
|---|---|---|
| `warp-all` | `{"type":"field","network":"tcp,udp","outboundTag":"warp"}` | всё, что не забрали правила выше |
| `warp-ai` | `{"type":"field","domain":[…],"outboundTag":"warp"}` | только домены AI-сервисов |

Сборка:

```bash
# весь трафик
./warp-vps.sh merge -c config.json -a node-1.account.json --all-traffic

# только AI
./warp-vps.sh merge -c config.json -a node-1.account.json \
  --rules "$(jq -r '._csv' templates/rules-ai.json)"
```

Список доменов и обоснование, что в него не вошло, — в
[templates/rules-ai.json](../templates/rules-ai.json).

## Куда встаёт правило и почему это важно

В обоих случаях правило вписывается **пятым**, после существующих:

```
0  DIRECT  inboundTag: dns_inbound        ← DNS остаётся прямым
1  BLOCK   ip: geoip:private
2  BLOCK   domain: geosite:private
3  BLOCK   domain: geosite:category-ads-all
4  warp    ← сюда
```

Порядок не косметический, каждая строка выше нашей что-то защищает:

- **`dns_inbound → DIRECT` должен остаться выше.** Иначе собственные
  DNS-запросы Xray пойдут в туннель, который в момент старта ещё не поднят.
- **`geoip:private` выше** — иначе при `--all-traffic` в туннель уедет трафик к
  приватным диапазонам, включая обращения внутри самого хоста.
- **BLOCK-правила выше** — реклама остаётся заблокированной и на AI-доменах,
  а не проксируется через WARP.

## Один аккаунт на ноду, а не на профиль

Профиль в панели можно назначить нескольким нодам. **Для WARP так делать
нельзя**: конфиг содержит `secretKey`, то есть все ноды с этим профилем получат
одну пару ключей WireGuard.

Для Cloudflare это один и тот же peer. WireGuard держит одну активную сессию на
peer и переносит её на адрес последнего валидного handshake — ноды начнут по
очереди перетягивать сессию на себя. Локально каждая выглядит здоровой,
пользователи получают рвущиеся соединения, воспроизвести не удаётся.

Поэтому «два профиля» — это два **шаблона**, а не два объекта в панели. На
каждую ноду заводится свой аккаунт и свой профиль:

```bash
./warp-vps.sh batch --count 3 --prefix node --out-dir ./nodes
```

Проверить, что ключи не разъехались по копипасте:

```bash
jq -r .public_key nodes/*.account.json | sort | uniq -d   # пусто = хорошо
```

## Чем платите за `--all-traffic`

Профиль «весь трафик» рабочий, но у него есть две цены, которые лучше знать
заранее, чем ловить под нагрузкой.

**CPU.** При `noKernelTun: true` весь трафик ноды проходит через userspace-стек
gVisor вместо ядра. На выделенных доменах это незаметно, на полном потоке —
становится основным потребителем CPU. Если контейнер ноды привилегированный,
`--kernel-tun` возвращает ядерный путь.

**Шейпинг Cloudflare.** Бесплатный WARP из датацентровых подсетей режется тем
сильнее, чем больше через него льют. Для полного туннеля имеет смысл WARP+:

```bash
./warp-vps.sh license -a node-1.account.json --key <ключ>
```

Померить, а не гадать:

```bash
./warp-vps.sh verify -a node-1.account.json   # факт выхода через WARP
# затем на ноде под нагрузкой:
top -p "$(pgrep -f 'xray' | head -1)"
```

Если CPU процесса Xray упирается в потолок — дело в userspace-стеке, и это
аргумент в пользу host-туннельной схемы для конкретно этой ноды.
